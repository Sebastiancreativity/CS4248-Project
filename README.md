# `official/` — Official Results, Code, and Process Records

This document records the source data, development-set construction, model-screening procedure, current screening results, and experiment history for the Chinese-to-English translation project. The original data in `official/` is preserved unchanged.

## 1. Original Data

The original datasets are stored in Canvas and must not be modified.

| File | Number of Lines | Description |
|---|---:|---|
| `train.zh-en.{zh,en}` | 15,406 | Course training data. It matches the ALMA-Human-Parallel zh-en dataset on Hugging Face, except for trailing spaces on 16 lines. |
| `wmttest2022.zh` / `wmttest2022.AnnA.en` | 1,875 | WMT22 test set with Annotator A references. Compared with the sacrebleu version, 4 lines contain one additional space. |
| `tatoeba.zh` | 469 | Tatoeba test set containing Chinese source sentences only, with no English references. All sentences are in Simplified Chinese. |

**Data-integrity rule:** Keep the original files unchanged. Any normalization, cleaning, or conversion should be performed on derived copies rather than on the originals.

## 2. Development Sets

Development sets were generated by `scripts/build_dev_sets.py` with random seed `4248`. The outputs are stored in `data/dev/`, and summary statistics are recorded in `data/dev/stats.json`.

All development sentences were deduplicated against both official test sets and the training set using exact matching after conversion to Simplified Chinese and removal of whitespace.

| Development Set | Sentences | Source | Intended Use / Benchmark | Average Length (Characters) | Sentences ≤15 Characters |
|---|---:|---|---|---:|---:|
| `dev_wmt` | 1,033 | WMT23 zh-en general test: news (527) and user_review (506), sampled by complete document (119 documents); manuals excluded | Benchmark aligned with the WMT22 test set (39.2 characters on average; 23% are ≤15 characters) | 41.5 | 22% |
| `dev_short` | 992 | Tatoeba cmn-eng (MTEB mirror), converted from Traditional to Simplified Chinese; 7 sentences overlapping with the official test set and 1 duplicate removed | Benchmark aligned with the Tatoeba test set (8.8 characters on average; 93% are ≤15 characters) | 11.0 | 87% |
| `dev_alma` | 1,002 | ALMA-Human-Parallel zh-en validation set (news) | Used for LoRA early stopping only; not used for candidate screening | 47.9 | 3% |

Each development set contains the following files:

- `.zh`: Chinese source sentences
- `.en`: English reference translations
- `.meta.jsonl`: sentence-level metadata, including ID, source, domain, document ID (`docid`), and whether Traditional-to-Simplified conversion was applied

**Evaluation protocol:** The official test sets are not used for model selection or for determining the MBR candidate pool. Model and candidate-pool decisions are made using the development sets.

## 3. Model-Screening Procedure

Run model screening with:

```bash
python scripts/screen_model.py --model <name>
```

The script uses a unified prompt, greedy decoding, and standardized output cleaning. It generates and evaluates translations on `dev_wmt` and `dev_short`.

### Outputs

| Output | Purpose |
|---|---|
| `results/screening/<model>/<dev_set>.hyp` | Cleaned translation hypotheses |
| `results/screening/<model>/<dev_set>.raw.jsonl` | Raw model outputs |
| `results/screening/screening.jsonl` | Consolidated screening records; new records are appended |
| `logs/` | Run logs |

Each result record includes the GPU power limit in effect during the run. The `sent_per_s` throughput metric should only be compared across runs with the same GPU power limit.

### Re-scoring After Cleaning Changes

If the output-cleaning rules change, use `--rescore` to re-clean and re-score saved raw outputs without generating translations again. In `screening.jsonl`, the latest record for a given model and development set is authoritative.

- `dev_wmt` represents longer, general-domain sentences, while `dev_short` emphasizes short sentences.

- Mixed Chinese/English, empty-output, and repetition rates are output-quality diagnostics.
- The GPU was software-limited to **30 W**, compared with its default limit of **80 W**, during the recorded screening run. Throughput was approximately one-tenth of normal. The experiment log reports no impact on translation-quality metrics from this power limit.
- Throughput comparisons are valid only when the GPU power limits match.
